CCM Soil Preprocessor — Concept Overview

ccm_soil_preprocess.py  ·  How raw soil data from any source becomes standardised USCS codes  ·  ArcGIS Pro 3.5+

The 3-Stage Pipeline

1
DETECT & MAP

Figure out what kind of soil data this is and where the soil info lives — which fields, tables, or files. Supports 8 named sources plus a generic fallback.

▶
2
NORMALISE

Convert whatever format the source uses (%, text class, WRB code, SMC integer, USDA order, plain name…) into a single two-letter USCS code via 7 ordered paths.

▶
3
GAP FILL

Data-driven only — no inference. Known non-soil polygons → NE. All remaining unknowns → NE. We never invent data that does not exist in the source.

How Auto-Detection Works

Detection priority (first match wins)

  • Field MUKEY → SSURGO
  • Field MU_GLOBAL → HWSD
  • Field POLY_ID + HECTARES + CMP file alongside → DSS
  • Field POLY_ID + companion GDB → SLC
  • Field SMC or SMCL → MGCP (default mil-topo)
  • GDB scan: SU_SFC present → MGCP
  • GDB scan: SurfaceCoverA present → TDS
  • GDB scan: SurfaceMaterialA present → GGDM
  • Filename: "ssurgo"/"statsgo" → SSURGO · "hwsd" → HWSD
  • Filename: "mgcp" → MGCP · "tds" → TDS · "ggdm" → GGDM
  • Anything else → Generic

Why a join chain instead of direct fields?

Most soil databases deliberately separate geometry from attributes to save space and allow many-to-one relationships (one polygon = multiple soil components at different depths). The preprocessor follows the official join paths, selecting the dominant surface component (highest PERCENT value in CMP) as the representative soil for CCM.


Military topographic sources (MGCP / TDS / GGDM) are simpler — the SMC code is directly on the polygon. The companion GDB is only used for the NE pre-pass: water bodies, built-up areas, rocky ground, and glaciers are stamped NE before soil classification runs.

Stage 3 — Data-Only Gap Fill (2 Passes)

Design principle: no inference — we never create data that does not exist in the source. Unknown = unknown. Both passes assign NE.

PASS 1 Known Non-Soil (Data-Driven)

DSS / SLC: If a polygon's POLY_ID was never found in the CMP table, the database itself tells us this polygon is water, rock, urban, or ice — not a soil unit.

  • Track which POLY_IDs had a CMP record (the matched set)
  • Any polygon not in matched set → stamp NE

MGCP / TDS / GGDM: The NE pre-pass spatially joins confirmed non-soil feature classes (water bodies, built-up areas, rocky ground, glaciers) onto the surface cover polygons.

Accuracy: ~95 %+
DSS, SLC (POLY_ID method) · MGCP, TDS, GGDM (spatial join method)
PASS 2 Unknown = NE

Any polygon still NULL after all normalisation paths and Pass 1 gets NE.

  • No spatial interpolation from neighbours
  • No statistical mode from the dataset
  • No assumption — if we have no data, we say so
  • Guarantees zero NULL polygons in the output FC

Why? CCM uses soil type for mobility scoring. Filling gaps with neighbour data or statistics introduces false confidence in areas with no ground-truth data. NE is the operationally honest answer.

Result: honest unknown — no invented data
Applies to: all sources

Recommended Data Stack — Layered by Geography

Layer 1 — US
SSURGO / STATSGO2
Highest accuracy anywhere (~90–95 %). Use for all continental US operations. gNATSGO covers SSURGO tile gaps.
Layer 2 — Canada
DSS → SLC fallback
DSS v3 at detailed scale. SLC v3.2 where DSS coverage is absent. Both use direct sand/silt/clay % (Path A).
Layer 3 — Global
SoilGrids 2.0 planned
Best global option once implemented (250 m, ML-modelled). Until then HWSD v2 covers the global gap at 1 km.
Layer 4 — Military AOI
MGCP / TDS / GGDM
Use SMC for soil where other sources have gaps. Most valuable role: NE pre-pass stamps water, rock, and urban areas at ~95 %+ accuracy regardless of which soil source is primary.
