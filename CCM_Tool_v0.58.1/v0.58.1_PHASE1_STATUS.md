### `ccm_data_fitness.py` — Role-Specific Fitness

Scoring for each role (1–10 per dataset per role):

**DEM:**
- Raster format: +3
- Vertical accuracy (<1m): +2
- Void-free (or SRTM void-filled): +2 or +3
- Resolution 10–30m: +2
- Example: "ASTER_30m.tif void-free = 10/10"

**Soil:**
- RCI calibration present: +3
- USCS recognition: +2
- Schema completeness (RCI + USCS cols): +2–3
- Moisture support: +2
- Example: "SoilGrids with RCI calibration = 9/10"

**Vegetation:**
- Format raster=+3, vector=+1
- Type: canopy=+3, NDVI=+2, classes=+1
- Resolution <30m: +2
- Example: "Canopy height raster 10m = 8/10"

**Hydrology:**
- Vector format: +4
- Type keywords (stream/river/flow): +3
- Coverage >50%: +2
- Example: "Stream network 80% coverage = 9/10"

**Contours:** Optional; elevation field=+3, polygon=+3, regularity=+1–2  
**Extent:** Polygon vector=+4, AOI keyword=+3, 100% coverage=+3  
**Vehicle CSV:** Table format=+3, VCI column=+3, required columns=+2, numeric sanity=+2

### `ccm_data_confidence.py` — Confidence Aggregation

Per-role thresholds:

```
IF (avg_score >= 8 AND coverage >= 95%):     → "High"
IF (avg_score >= 6 AND coverage >= 80%):     → "Moderate"
IF (avg_score >= 3 AND coverage >= 50%):     → "Low"
ELSE:                                         → "Unvetted"
```

Model-level (all 7 roles):

```
IF all critical roles (DEM, Extent, Vehicle) are High or Moderate:
    "Acceptable" → proceed
ELIF any critical role is Unvetted:
    "At-Risk" → escalate
ELIF any warn role (Soil, Veg) is Low:
    "Conditional" → proceed with cautions
ELSE:
    "Incomplete" or "At-Risk"
```

Example output:
```json
{
  "DEM": {"confidence": "High", "quality": 8, "fitness": 8, "coverage": 95},
  "Soil": {"confidence": "Low", "quality": 5, "fitness": 4, "coverage": 85},
  "model_confidence": "Conditional",
  "warnings": ["⚠ Soil data unvetted; validate RCI manually"],
  "recommendations": ["Validate Soil before Step 2"]
}
```

### `ccm_data_readiness.py` — Preprocessing Validation

9-point checklist:

```
□ DEM: exists, raster, projected CRS
□ Slope: exists, valid values [0–90]
□ Soil: exists, RCI table linked
□ Vegetation: exists, raster format
□ Hydro: optional; valid if present
□ Extent: polygon, ≥1 feature
□ Vehicle CSV: required columns, numeric values
□ Workspace: writeable, accessible
□ Configuration: ccm_project.json valid
```

Readiness status:
- **Ready:** 100% items checked
- **Mostly Ready:** 80–99% (minor rework)
- **Partial:** 50–79% (significant rework)
- **Incomplete:** <50% (cannot proceed)

Example output:
```json
{
  "readiness_status": "Mostly Ready",
  "readiness_pct": 85,
  "next_steps": [
    "⚠ Minor rework needed before Step 2:",
    "  • Soil: Soil RCI lookup table not found; manual calibration needed",
    "  Re-run Step 1 or add missing layers"
  ]
}
```

## Key Design Decisions

1. **No external dependencies:** Uses only Python stdlib (+ optional arcpy). Easy to test on any Python.

2. **Graceful degradation:** All checks work without arcpy; CRS/raster validation improved when arcpy available.

3. **Composable scores:** Quality → Fitness → Confidence → Readiness → Auto-Selection. Each layer feeds forward.

4. **Human-readable output:** Every score includes `reasoning` text explaining the decision.

5. **Conservative defaults:** Unknown values = neutral (5.0) or no penalty. Scores only downgrade on explicit problems.

6. **Role-centric:** Each dataset scored per role. One dataset can be fit for multiple roles (e.g., DEM as elevation source AND slope input).

7. **Critical role awareness:** Model-level confidence gated on DEM/Extent/Vehicle status; Soil/Veg warnings only.
