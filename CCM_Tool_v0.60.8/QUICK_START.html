CCM Tool v0.60.1

Integrated ArcGIS Pro toolbox + single-root project architecture

Operator quick start

New in v0.60.x

Every step (0, 0b, 1, 2, 3) now shares ONE Project Root Folder instead of a separate folder per step. Point every dialog at the same folder and Step 0/0b create the shared layout automatically.

What stays stable

The v0.57 factual inventory, Steps 0-4 mobility models, and the Quality/Fitness/Confidence/Readiness scoring + recommendation engine are unchanged — only how projects are set up and located changed.

Recommendation workflow

Step 0b scores all datasets → generates recommendations → Step 1 displays them → you accept or choose an alternative → proceed to Steps 2-4.

1. Prepare and verify

Open Anaconda Prompt, change to the CCM_Tool_v0.60.1 folder, then run:

CCM_anaconda.bat
RUN_TESTS.bat

The default environment is ccm_tool (Python 3.11, pytest, pyflakes, PyInstaller). CCM_anaconda.bat also runs conda activate for you, so this Anaconda Prompt is left inside ccm_tool when it finishes — no separate activation step needed. test_single_root_pure_python.py additionally verifies the single-root rewrite itself (45 checks, no arcpy needed).

For GeoPackage/file-geodatabase layer enumeration, install optional GDAL/OGR:

CCM_anaconda.bat ccm_tool_gdal --with-gdal
set CCM_ENV_NAME=ccm_tool_gdal
RUN_TESTS.bat

2. Set up a project folder (single-root layout)

Every step shares ONE Project Root Folder. Let Step 0 or Step 0b create the layout automatically the first time you point either at a folder, or set it up ahead of time with the standalone Project Initializer (no arcpy needed):

python ccm_project_init.py

Pick a folder and it creates ccm_project.json, 01_Input_Data/, and 02_Scan_Index/ in it (03_Project.gdb follows once Step 0 or Step 1 runs). Or freeze it into a standalone .exe with build_project_init_exe.py.

3. Add the toolbox

  1. Open ArcGIS Pro and a project.
  2. Catalog pane → right-click Toolboxes → Add Toolbox.
  3. Select CCM_Tool_v0.60.1.pyt.
  4. Confirm six entries: Step 0, Step 0b, Step 1, Step 2, Step 3, and Step 4.

4. Recommended first run

Step 0Optional MGCP consolidation. Point at your Project Root Folder.
Step 0bScan the same Project Root Folder; scores and recommends sources per role.
Step 1Same folder again. Review recommendations; accept or override; preprocess inputs.
Steps 2-4Same folder throughout. Generate mobility maps and run analyses.
Step 0b outputs (written to <Project Root>\02_Scan_Index\): ccm_data_catalog.json, CCM_Data_Intelligence_Report.html (factual inventory), CCM_Recommendations_Report.html (auto-selection), ccm_quality_scores.json, ccm_fitness_scores.json, ccm_confidence_scores.json, ccm_readiness_scores.json, ccm_recommendations.json (machine-readable). ccm_project.json itself lives directly in the Project Root Folder.

5. Standalone scan options

Use the logged command-line launcher for a real Project Root Folder:

RUN_DATA_SCAN.bat "D:\GIS\Project" "D:\GIS\Project\01_Input_Data\Extent\AOI.shp"

Or launch the safe standalone GUI (single-root aware — it scans 01_Input_Data when populated, or the root itself otherwise):

CCM_Data_Scanner.bat

6. ArcPy smoke test

ArcPy requirement: ArcPy comes from a licensed ArcGIS Pro installation. Open and sign in to ArcGIS Pro before running the test.
RUN_ARCGIS_SMOKE_TEST.bat

Runs all seven licensed tests: Steps 0-3, the single-root dialog-behavior test (Vehicle dropdown scenarios, Step 3 GDB-resolution fallback), the factual Step 0b test, and the integrated Step 0b test. Test data is written only below verification_artifacts; results and logs are saved under verification_logs.
